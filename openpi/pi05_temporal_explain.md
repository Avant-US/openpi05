# Pi0.5 时序相关问题详解

## 1. Markovian 与 Non-Markovian
### Markovian（马尔可夫性）
下一步只取决于当前状态，跟历史无关。
```
例：下棋
当前棋盘局面 → 就能决定下一步怎么走
不需要知道之前是怎么走到这个局面的
```
### Non-Markovian（非马尔可夫）
光看当前不够，必须看历史。
```
例：开门
当前画面：手在门把手上
但光看这一帧你不知道：
- 门把手按下去了没？
- 门锁解开了没？
- 门是往里推还是往外拉？（之前试过推没推动吗？）
必须看之前的帧才能判断
```
数学表达：
- Markovian: $$a_t = f(s_t)$$
- Non-Markovian: $$a_t = f(s_t, s_{t-1}, s_{t-2}, \dots)$$
### 机器人操作中常见的 Non-Markovian 场景
| 场景 | 当前帧看到的 | 看不出但很重要的 |
|------|------------|----------------|
| 开门 | 手在把手上 | 门锁解了没、把手按下去了没 |
| 拧瓶盖 | 手在盖子上 | 已经拧了几圈、松了没 |
| 擦桌子 | 手拿着抹布 | 哪块区域已经擦过了 |
| 叠衣服 | 手在衣服上 | 前两个角折好了没 |
### Pi0.5 与马尔可夫假设
Pi0.5 当前只看**一帧图像**做决策，本质上假设任务是 Markovian 的。对开门这种 Non-Markovian 任务，需要额外的历史信息才能做好。

## 2. 交错视觉标记（Interleaved Visual Tokens）
### 概念
从历史中挑选几帧关键帧，把它们的视觉 token 和当前帧的 token **穿插排列**在一个序列里，一起送进 Transformer。
### Pi0.5 现在的输入
```
[当前帧的256个视觉token, 语言token]  →  Gemma
```
### 加入关键帧后的输入
```
[关键帧1的视觉token, 关键帧2的视觉token, 当前帧的视觉token, 语言token]
      ↑                    ↑                     ↑
   30秒前门还关着       5秒前手按下把手           现在
```
### 效果对比
没有关键帧：
```
模型看到: [当前这一帧]
模型心想: 手在门把手上...然后呢？不知道之前发生了啥
```
有关键帧：
```
模型看到: [30秒前的帧, 5秒前的帧, 当前帧]
模型心想: 30秒前门关着 → 5秒前按下了把手 → 现在该拉了
```
### 为什么不直接喂连续视频帧？
```
方案A: 喂连续30帧（每帧256 token）→ 7680个token，太长了，算不动
方案B: 只挑3个关键帧交错放进去 → 768个token，能算，且信息量更大
```
### 术语解释
- **交错** = 不同时间点的图像 token 穿插排列在一个序列里
- **锚定** = 模型的决策被关键帧"钉住"，不再只凭当前帧盲猜
- **长时域时序上下文** = 关键帧可能跨越几十秒甚至几分钟，提供长期历史

## 3. Pi0.5 的 Transformer 怎么体现时序？
### 核心事实：Pi0.5 的 Transformer 处理的不是时间序列，是 token 序列
```
Transformer 输入序列（全部来自同一时刻）：
[vis₁, vis₂, ..., vis₂₅₆, lang₁, lang₂, ..., lang_L, act₁, act₂, ..., act_H]
 \______视觉token______/  \____语言token____/         \_____动作token_____/
全部是【同一时刻】的信息！
```
- 视觉 token：当前帧图片拆成的 256 个 patch
- 语言 token：指令"打开门"分成的几个词
- 动作 token：要预测的**未来 H 步**动作
### 时序靠 Action Chunking（动作分块）
Pi0.5 一次推理预测**未来 H 步**的完整动作序列：
```
时刻 t 的一次推理:
  输入: 当前帧图像 + "打开门"
  输出: [a_t, a_{t+1}, a_{t+2}, ..., a_{t+H-1}]
         ↑     ↑       ↑              ↑
        现在  0.03秒后  0.06秒后      H步后
```
然后执行一部分，拍新照片，重新预测：
```
t=0: 拍照 → 预测 [a₀, a₁, ..., a₄₉]  → 执行前几步
t=4: 拍照 → 预测 [a₄, a₅, ..., a₅₃]  → 执行前几步（和上次完全独立）
t=8: 拍照 → 预测 [a₈, a₉, ..., a₅₇]  → ...
```
**每次推理之间完全独立，没有记忆。**
### 和 LSTM 的本质区别
```
LSTM:
  t=0: 看帧₀ → 隐状态h₀ → 动作a₀
  t=1: 看帧₁ + h₀ → h₁ → a₁     ← h₁记住了帧₀的信息
  t=2: 看帧₂ + h₁ → h₂ → a₂     ← h₂记住了帧₀和帧₁
  → 有"记忆"，每步带着历史信息
Pi0.5:
  t=0: 看帧₀ → [a₀, a₁, ..., a₄₉]      ← 一次出50步
  t=4: 看帧₄ → [a₄, a₅, ..., a₅₃]      ← 重新算，和上次完全无关
  t=8: 看帧₈ → [a₈, a₉, ..., a₅₇]      ← 又是独立的一次
  → 无记忆，每次从头看当前帧
```
### Pi0.5 为什么还能完成任务？
1. **Action Chunking 提供短期时序**：一次预测 50 步（约 1-2 秒），这 50 步之间通过 Transformer 内部 action token 之间的 attention 保证连贯性
2. **当前帧隐含部分历史**：手已经握住门把手、门已开了一条缝，这些在图像里能看出来
### 但不够的时候
- 门把手按下去了但视觉上看不出来
- 门锁转了 90° 但从外面看不出来
- 模型不知道之前发生了什么 → 这就是需要加关键帧的原因
### 总结
| 维度 | Pi0.5 现状 | 靠什么 |
|------|-----------|--------|
| 过去 | ❌ 没有记忆 | 全靠当前帧能看出多少 |
| 未来 | ✅ Action Chunking | 一次预测 H 步连贯动作 |
| 序列内 | ✅ Attention | 视觉/语言/动作 token 互相注意 |

**Pi0.5 的 Transformer 不处理时间序列，只处理空间序列（token 之间的关系）。加关键帧就是给它补上缺失的"过去"维度。**
